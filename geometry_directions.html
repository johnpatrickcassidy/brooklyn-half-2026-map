Road Network Snap - Architecture Directions

Problem Statement: The initial map relies on two-point straight line segments. For curving corridors like Parkside Avenue or highway merge roads, straight lines visually cut through city blocks and parks rather than tracing the true physical street network.

Below are three implementation avenues to achieve high-fidelity road snapping. Compare the live demos (demonstrating straight vs snapped geometries on Parkside Ave) and copy the prompt for your preferred technical path.

Option 1: Runtime OSRM Routing API

Dynamically queries the public Open Source Routing Machine (OSRM) driving API at map load time. Passes start/end points, extracts the road-aligned GeoJSON geometry, and plots the customized polylines.

Trade-offs:
  • Highly accurate street mapping
  • Zero static storage overhead
  • Runtime API dependency (requires network fetch)

Option 2: Pre-compiled Dense Geometries

Pre-calculates the dense coordinate arrays offline once and permanently embeds the high-fidelity line paths directly into data.js. Maintains the entire project as an independent static site.

Trade-offs:
  • Ultra-fast rendering (no runtime API lags)
  • 100% offline-capable client architecture
  • Substantially increases the source file size of data.js

Option 3: Mapbox GL / Google Maps Engine

Migrates the base tech stack from standard Leaflet to Mapbox GL JS or Google Maps API. Utilizes premium backend map matching services to natively bond custom vector layers to actual road network segments.

Trade-offs:
  • Industry standard rendering performance
  • Advanced isometric camera and layering options
  • Requires dedicated platform API key configurations
